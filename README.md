# MediaMaker

Самостоятельный проект создания и публикации контента. Не зависит от Lero VPN.

## Компоненты

- `news-editor/` — действующий редактор BAGLER NEWS: поиск новостей, российский audience-фильтр, генерация иллюстраций, очередь и ручная публикация через Telegram.
- `server/` — отдельный прототип API и бота для загрузки контента. Не подключать к токену действующего редактора: два polling-процесса будут конфликтовать.
- `frontend/` — стартовый React/Vite-шаблон, пока не рабочая панель редактора.
- `deploy/` — production unit новостного редактора.

## Production

Сервер: `control1` (`ru1.bagsar.com`). Код всего проекта размещается в `/opt/mediamaker`.
Активен только `bagler-news-editor.service`, запускающий `/opt/mediamaker/news-editor/bagler.js` на Node 24.
Существующее имя службы сохранено для совместимости мониторинга и прав DynamicUser.
Секреты остаются в `/etc/bagler-news-editor.env`, данные и очередь — в `/var/lib/bagler-news-editor`.
Они не входят в репозиторий. VPN-сервисы не являются зависимостями этого проекта.

Проверки без запуска бота: `cd news-editor && npm ci && npm test` (Node 24).
Не запускайте `bagler.js` локально с production-токеном.

API-прототип и frontend загружены на сервер как исходники, но не опубликованы в интернете.
Перед публичным запуском API необходимы проверка доступа к данным, обязательный секрет JWT,
настройка регистрации, отдельное хранилище, HTTPS и интеграция панели с действующей очередью.

## Перенос 27 сентября 2026

Полный production-редактор восстановлен с сервера в `news-editor/`, включая отсутствовавшие
в VPN-репозитории AI-модули, хранилище, обработку изображений и ресурсы. Все совпадающие
файлы сверены без различий, четыре audience-теста прошли на серверном Node 24.
Служба переключена на новый путь; база, очередь, изображения, секреты и расписание сохранены.
Старый код и unit сохранены только для отката в `/opt/mediamaker-migration-backup-20260927/`.
Там же находится архив состояния, созданный при остановленной службе.
Откат: остановить редактор, вернуть `editor-original` в `/opt/bagler-news-editor`,
восстановить сохранённый unit в `/etc/systemd/system/`, выполнить daemon-reload и запустить
службу. Не восстанавливать старую базу поверх новых публикаций без отдельного решения.
